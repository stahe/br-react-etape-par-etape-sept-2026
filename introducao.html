    Este documento é um produto da IA Claude da Anthropic. Ele segue o curso “Introdução passo a passo ao framework web NestJS”, do qual muda a perspectiva:

    • No curso [NestJS], o servidor gera as páginas HTML (engine de views [Handlebars]); o navegador apenas as exibe;
    • neste curso, as páginas são geradas no navegador por uma aplicação [React]; o servidor, agora reduzido a um simples servidor JSON, fornece apenas dados.

    As páginas da aplicação, porém, permanecem as mesmas: são as da aplicação [RdvMedecins] já apresentada com os outros frameworks (login com CAPTCHA, agenda do médico, janela de consulta, portal do paciente, gerenciamento de médicos e clientes, criação de conta, francês e inglês).

    Este documento segue a mesma estrutura de seus antecessores: primeiro, vários exemplos curtos, cada um focado em um conceito específico do [React], seguidos de um estudo de caso completo — o cliente [React] da aplicação [RdvMedecins] — com todos os arquivos comentados. Ele segue a mesma estrutura dos cursos *Introdução passo a passo ao framework Vue.js* e *Introdução passo a passo ao framework Angular*: os leitores familiarizados com [Vue.js] ou [Angular] encontrarão os mesmos exemplos, escritos no estilo do [React]: 25 exemplos, numerados como os do curso [Angular].

    Já existe um curso sobre este tema: Um exemplo cliente/servidor React / NestJS (2026), que cobre tanto o servidor quanto o cliente. Este documento difere daquele em sua abordagem: o servidor é tratado como uma caixa-preta, e nos interessamos apenas pela API e pelo JSON; aprendemos [React] passo a passo antes de abordar o cliente completo.

    1.1. O papel do React em uma aplicação web

    A aplicação tem duas partes, que se comunicam entre si apenas por meio de requisições:

    • 1: A aplicação [React], executada no navegador, envia uma requisição HTTP ao servidor, por exemplo, [GET /api/schedule?doctorId=1&day=2026-10-05];
    • 2: O servidor responde com dados JSON: a agenda desse médico para aquele dia. Ele não gera nenhuma página;
    • 3: Com esses dados, o [React] atualiza a página exibida no navegador sem recarregá-la.

    O diagrama a seguir compara as duas arquiteturas:

    O navegador carrega apenas uma única página HTML, quase vazia, na inicialização. Todo o resto é gerado pelo código [JavaScript]: é o que se chama de aplicação de página única (SPA, de [Single Page Application]). Quando o usuário clica em um link interno, nenhuma página é solicitada ao servidor: o roteador altera a URL exibida e substitui o conteúdo da página.

    [React] é uma biblioteca criada pelo [Facebook] (hoje [Meta]) e lançada em 2013. Atualmente, é a biblioteca mais usada para construir interfaces web. Ela se baseia em três conceitos:

    • componentes: a interface é dividida em partes reutilizáveis (uma barra de navegação, um campo de formulário, uma janela de confirmação etc.). Um componente [React] é uma simples função [JavaScript] (ou [TypeScript]) que retorna o que deve ser exibido, escrita em JSX, uma sintaxe que combina HTML e [JavaScript];
    • Estado e renderização declarativa: os dados de um componente ficam armazenados em seu estado ([useState]). Quando o estado muda, o [React] chama a função do componente, compara o resultado com o anterior e atualiza automaticamente o que mudou na página. Nunca escrevemos código que modifica diretamente a página: descrevemos a página em função do estado;
    • hooks: funções ([useState], [useEffect], [useContext]...) por meio das quais um componente acessa os mecanismos do [React]: estado, efeitos colaterais e dados compartilhados. Você pode escrever seus próprios hooks para reutilizar um comportamento.

    Diferentemente do [Angular], o [React] não é um framework "tudo em um": é uma biblioteca de renderização. O roteador, os formulários, o cliente HTTP, a tradução e o estado compartilhado são fornecidos por outras bibliotecas, escolhidas pelo desenvolvedor. Este curso usa as mais comuns: [React Router] (o roteador), [React Hook Form] (uma biblioteca de formulários de exemplo), [TanStack Query] (leitura de dados do servidor), [Zustand] (estado compartilhado) e [i18next] (idiomas). A ferramenta de build é o [Vite].

    Usaremos o [React] 19, com sua implementação mais recente: componentes de função e hooks (os antigos componentes escritos como classes não são mais usados), actions de formulário ([useActionState]), [use()] e [<Suspense>], [<title>] posicionado por um componente, [useEffectEvent] e [<Activity>] (React 19.2).

    1.2. Ferramentas utilizadas

    Os exemplos foram escritos e testados com as seguintes ferramentas (as instruções de instalação estão no apêndice):

    • [Node.js] 24 (ou pelo menos 22.22: é uma exigência do [React Router] 8) e seu gerenciador de pacotes [npm];
    • o editor [Visual Studio Code], que inclui suporte a [TypeScript] e JSX sem nenhuma extensão adicional;
    • um navegador recente ([Chrome], [Firefox], [Edge]), se possível com a extensão [React Developer Tools];
    • a ferramenta de linha de comando [curl], que exibe as respostas HTTP brutas;
    • o SGBD [MySQL] (ou [MariaDB]), por exemplo, o do [Laragon] no [Windows]: ele é necessário para o servidor JSON, conforme descrito no capítulo que o apresenta.

    As bibliotecas são as dos arquivos [package.json]: [React] 19.3, [React Router] 8.4, [Vite] 8.3, [TypeScript] 6.0, [React Hook Form] 7.89, [TanStack Query] 5.104, [Zustand] 5.0, [i18next] 26 e [react-i18next] 17, [Bootstrap] 5.3.

    Instale as bibliotecas uma única vez, em um console aberto na pasta [examples-react] (no [VS Code]: menu Terminal / Novo Terminal):

    npm install

    Depois, execute um exemplo digitando seu nome:

    npm start 01-first-application

    O servidor de desenvolvimento do [Vite] serve o exemplo na porta 5173: abra-o em http://localhost:5173/. Esse servidor não precisa ser reiniciado quando você modifica um arquivo: cada arquivo salvo é recompilado imediatamente e a página do navegador é atualizada automaticamente, normalmente sem nem perder seu estado. Interrompa-o digitando [Ctrl-C] no console antes de executar o exemplo seguinte (apenas um exemplo por vez pode ocupar a porta 5173).

    Os exemplos 22 a 25 consultam os servidores JSON e [RdvMedecins]: será preciso tê-los instalado e iniciado, conforme explicado no capítulo dedicado a eles.
